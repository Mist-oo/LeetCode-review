# 第二版：Hot 100 本机 ACM 判题

确认日期：2026-10-29。第二版变更以本文为准，第一版记录和笔记数据继续保留。

## 已确认范围

- 只保留 Hot 100 的 100 道题；删除自选题添加入口，既有自选数据留在数据库但不显示、不参与复习或判题。
- Python 完整程序，连续读取到 EOF，不使用组数 T，不提供代码模板。每题显示明确的输入输出协议、组边界和可复制的多组样例。
- 数组用长度和元素表示，矩阵用尺寸和逐行数据，树用带 null 的层序序列；字符串单独规定长度和空行处理。每组输出的边界必须可解析，多解使用题意校验器。
- 运行：少量公开样例或自定义输入，不写正式提交历史。
- 提交：固定且带版本号的完整测试集，保存每次代码、时间、结果；另外提供可选随机加强测试。
- 默认隐藏测试输入和期望答案，显示状态、通过组数、进度；可主动揭示首个失败用例，支持取消。
- 每个批次一个进程，多组 EOF 输入检查组间状态；另有独立压力批次。以多数提交约 10 秒为性能目标，重题可更久，不靠删边界覆盖提速。
- 本机 Python 子进程，不依赖 Docker；工作目录隔离、时间/输出限制、可执行的内存监控和子进程清理。此方式不是安全沙箱，只运行个人代码。
- 判题与复习结果独立：✅／❌始终手动决定。保存每日记录时只关联相同代码对应的判题结果，不能沿用修改前代码的通过状态。
- 开启本地 Python 上下文补全，支持变量、方法、导入和参数提示，可开关，无 AI 续写。
- 保留矩阵、草稿、错误标签、长期笔记、历史查看与随机复习。每天每题仍一条手动记录，可有多次正式提交。

## 质量门槛

每道题必须有普通、合法边界、极端规模、固定随机与多组状态用例。小规模数据用独立暴力解或独立枚举验证器核对，测试集应能拒绝常见错误程序。多解校验必须检查遗漏、重复和无效答案。每题保留可审计的覆盖清单和验证结果。

不宣称拥有或等同力扣隐藏测试集，也不声称有限用例证明所有输入正确。ACM 只验证可观察输出与运行表现，原地操作、深拷贝等内部实现要求由使用者自查。

## 开发阶段及完成条件

1. 协议与判题题库：100/100 唯一协议、样例、参考计算与输出解析；不同合法答案可通过。
2. 数据质量：逐题验证合法数据、独立小规模对照、典型错误拒绝、极端规模覆盖；固定版本可复现，随机加强保留种子。
3. 执行器：EOF 批次、超时、内存/输出过量、异常、取消、进度和清理经过真实子进程测试。
4. 持久化与 API：异步提交状态、所有正式提交历史、失败用例按需揭示、代码快照一致关联、旧数据迁移不丢失。
5. 网页：运行/提交/随机加强、结果/提交历史、揭示和取消、补全开关、删除自选入口；进行浏览器验收。
6. 启动与交付：安装依赖说明、完整回归与题库质量报告、性能实测、真实项目启动验证；每个可验证阶段更新日志并提交推送。
